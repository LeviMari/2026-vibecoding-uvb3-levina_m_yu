Улучши моего Telegram-бота, добавив работу с данными: базу данных SQLite, Google Календарь (по iCal-ссылке или .ics файлу) и выгрузку в Excel.

ТЕКУЩИЙ ФУНКЦИОНАЛ БОТА (весь код в этой папке, изучи его перед изменениями):
Личный ассистент по задачам и встречам на python-telegram-bot 21 (async, job-queue). LLM вызывается через OpenAI-совместимый API (httpx, модуль llm.py). Модули: bot.py (запуск), handlers.py (команды, текст, файлы, кнопки), llm.py (все промпты), storage.py (хранилище data.json), jobs.py (уведомления), keyboards.py, dates.py, config.py.
Бот умеет: разбирать .txt саммари встреч и предлагать задачи кнопками (у каждой встречи свои кнопки), добавлять задачи обычным текстом, менять статусы фразами («отчёт сделала»), отвечать на вопросы по истории встреч, /tasks (нумерованный список с кнопками «Готово N» / «В работе N»), /done, /week (план на оставшиеся дни недели), /meetings, /review, /settings, уведомления (будни 9:00, 18:00 накануне дедлайна, 15:00 в день дедлайна).

ВАЖНО — НЕ СЛОМАТЬ:
- Весь существующий функционал и тексты бота должны продолжать работать.
- В bot.py перед run_polling есть asyncio.set_event_loop(asyncio.new_event_loop()) — это нужно для Python 3.14+, не удаляй.
- В bot.py логгер httpx поднят до WARNING, чтобы токен бота не попадал в логи — сохрани. Секреты (токены, ключи, iCal-ссылки) никогда не выводить в логи.
- В llm.py у classify_intent есть список открытых задач и правила с примерами, а в handlers.py — страховка: сообщение без «?» сначала пробует найти задачу. Сохрани это.
- dates.plan_days() и логика плана только на оставшиеся дни недели — сохрани.

НОВЫЙ ФУНКЦИОНАЛ:

1. SQLite вместо data.json
- Модуль db.py на встроенном sqlite3. Путь к базе из .env: DB_PATH (по умолчанию bot.db рядом с кодом) — чтобы потом на хостинге положить базу на постоянный диск.
- Таблицы: users (user_id, chat_id, name, notifications_enabled, calendar_url, created_at), tasks (id, user_id, title, deadline, priority, status, source_meeting_id, created_at, completed_at, updated_at), meetings (id, user_id, date, title, participants JSON, summary JSON, decisions JSON, created_at), pending_tasks (задачи, предложенные из встречи и ещё не добавленные), week_plans (user_id, plan JSON, created_at), feedback (id, user_id, text, created_at), events (id, user_id, action, created_at) — журнал действий для статистики.
- Индексы по user_id, status, deadline.
- Автоматическая миграция: если при старте есть data.json, а база пустая — перенести всех пользователей, задачи, встречи и предложенные задачи в SQLite, а data.json переименовать в data.json.migrated (не удалять). В лог — сколько записей перенесено.
- Переписать storage.py так, чтобы остальной код менялся минимально (сохрани интерфейс get_user / save_user / all_users там, где это разумно, или аккуратно перепиши вызовы).

2. История и статистика (то, что даёт база)
- /stats — личная статистика: задач закрыто за эту неделю и за 30 дней, сколько открыто, сколько просрочено, 3 самые «старые» открытые задачи (сколько дней висят), сколько встреч загружено за месяц.
- Новый intent в classify_intent: history — вопросы вида «что я сделала за последние 2 недели?», «какие задачи закрыла в сентябре?». Бот делает SQL-выборку за период (период определяет LLM, возвращая date_from/date_to в JSON) и выводит список.
- Раз в неделю (пятница 17:00) напоминание о «забытых» задачах: открыты больше 14 дней без изменений — кнопки «Ещё актуально» (обновляет updated_at) и «Удалить».

3. Google Календарь
- /calendar — подключение календаря. Бот объясняет, как получить в Google Календаре «Секретный адрес в формате iCal» (Настройки → выбрать календарь → Интеграция календаря), и ждёт ссылку. Ссылку проверить (скачать и распарсить), сохранить в users.calendar_url, сообщение пользователя со ссылкой попытаться удалить из чата (ссылка секретная) и сказать об этом. Также принимать файл .ics (экспорт календаря) — если ссылку получить нельзя.
- /calendar при уже подключённом календаре — показать статус и кнопки «Обновить ссылку» / «Отключить».
- Парсинг: библиотеки icalendar и recurring-ical-events (обязательно учитывать повторяющиеся встречи), скачивание через httpx. Все времена переводить в TIMEZONE из .env. Кэшировать события пользователя в памяти на 15 минут, чтобы не скачивать календарь на каждый запрос.
- Учитывать только встречи с временем начала и конца (не события на весь день), исключать отменённые (STATUS:CANCELLED).
- /today — встречи сегодня (время, название) + задачи с дедлайном сегодня и план дня.
- /week — при построении плана передавать LLM для каждого доступного дня занятость: список встреч и сколько часов свободно в рабочем окне 10:00–19:00. Правило: в день с меньше чем 3 свободными часами — не больше 1–2 задач. В выводе плана у каждого дня показывать «📅 N встреч, свободно ~X ч».
- Утренняя сводка в 9:00 — добавить список встреч на день.
- Напоминание после встречи: задача каждые 10 минут проверяет, закончилась ли у пользователя встреча (длительностью от 15 минут) за последние 10 минут — и пишет: «Встреча «<название>» закончилась. Пришли саммари — разберу задачи». Одно напоминание на встречу (запоминать uid+дату в базе). Можно выключить в /settings отдельным переключателем.
- Если календарь не подключён — всё работает как раньше, без ошибок.

4. Выгрузка в Excel
- /export — файл tasks_<дата>.xlsx (библиотека openpyxl) с листами: «Открытые задачи», «Выполненные» (за 30 дней), «Встречи» (дата, тема, решения). Шапка жирная, ширина колонок по содержимому, даты в формате ДД.ММ.ГГГГ. Отправить пользователю документом.

5. Обратная связь и статистика использования (для следующей лабораторной)
- /feedback — бот просит написать отзыв одним сообщением и сохраняет его в таблицу feedback, благодарит.
- Логировать в events действия: start, meeting_upload, task_add, task_done, question, week, review, export, calendar_connect, feedback.
- /admin — только для ADMIN_ID из .env: число пользователей, активных за 7 дней, сколько встреч/задач/вопросов всего, последние 5 отзывов.
